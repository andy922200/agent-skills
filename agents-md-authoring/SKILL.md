# agents-md-authoring

## 何時使用

- 新建、精簡或拆分 `AGENTS.md`。
- 決定一段知識該放核心檔、某份 guide、README，還是不寫。
- 新增一份 guide，或發現同一件事在多處各寫了一次。

## 單一正本，避免重複

**每個事實只在一處完整寫出。** 其他地方只放連結，旁邊最多一句不會過期的用途說明，不複述內容。重複是文件失真的主因：兩處同時存在時，更新總會漏掉其中一處，而讀者（尤其代理）會相信沒更新的那份。

新增或搬移任何一段之前，先問：

1. 別處已有這個事實的正本嗎？有就連過去。
2. 能從程式、設定檔、`package.json` 直接讀到嗎？能就不抄，例如版本號、路由清單、常數值、筆數、輪詢次數。一定要抄時只抄一處，並註明來源檔。
3. 改了這一處，會不會逼我改第二處？會，就是重複。

常見的重複型態：

| 型態 | 處置 |
|---|---|
| README ↔ AGENTS／guides（技術堆疊、目錄樹、指令表、環境需求） | 依讀者指派正本：人類上手流程歸 README，AI 工作規則歸 guides，另一邊改成連結 |
| guide ↔ guide（同一張表、同一條規則） | 指派一個主題擁有者，其餘連結 |
| 同一檔內兩節講同一件事 | 合併，只留一處 |
| 文件表格 ↔ 程式常數 | 以程式為正本；文件若保留對照表，註明來源檔，程式端註解也指回文件 |
| 核心硬性禁令 ↔ guide 細則 | 禁令全文只在核心檔，guide 一句帶過並連結 |
| 摘要 | 摘要同樣會過期，只寫語意，不寫數字 |

做法：

- 動手前先列「正本指派表」：主題 → 唯一位置 → 其他處怎麼處理。拆分或搬移時把這張表給使用者看。
- 選哪份當正本、AI 指令要不要從人類文件移走，是使用者的決定，用提問確認。
- 事後驗證：對每個專有名詞、數字、指令 `grep`，確認只有一處有完整敘述。

## 核心 AGENTS.md 放什麼

- 放：一段專案概述、指引索引、硬性禁令、AI 協作約定（輸出語言、查文件規範、完成前驗證）。
- 不放：會變動的清單與進度（品牌、筆數、狀態）、能從程式讀到的事實、只有特定工作才會用到的細節（移進 guide）。
- 判準是「每個 session 都用得到嗎」，不是檔案大小。參考實例：anki-sprache 從約 41 KB 精簡到約 8 KB，這只是結果，不是門檻。

## 拆分成 guides

- **依動手情境切**（改前端、改後端、動安全、部署），不沿用原本的章節字母。一份 guide 對應一種工作。
- 資料夾與 `.agents/skills/` 並列，例如 `.agents/guides/`。不要取名 `rules`，以免與 Claude Code 會自動掃描的 `.claude/rules/` 混淆。
- 每份檔頭寫一句「用途」與「相關」連結，讓讀者知道何時該讀、讀完還該看什麼。
- 核心檔放**索引表**（要做的事 → 先讀哪份），表上方加強制語：動手前先讀對應檔案，跨領域任務讀多份。硬性禁令留在核心檔，作為沒讀 guide 時的最後防線。
- 交叉引用一律用相對連結，不用章節字母編號，拆分後編號會失效。
- 先逐段搬移、不改寫，再另外修內容，diff 才好 review。
- 同步改外部引用（README、程式註解、其他文件指到舊章節的連結），並 `grep` 確認無殘留。

## 載入機制

以下依 2026-10 的 Claude Code 官方 memory 文件，使用前請重新確認：

- `@path` 匯入在載入時展開，**不是**延遲載入，不會省 context。
- `.claude/rules/*.md` 加 `paths:` frontmatter，才會在讀寫到符合路徑的檔案時才載入，但只有 Claude Code 認得。
- 目錄同時有 `AGENTS.md` 與 `CLAUDE.md` 時，Claude Code 只讀 `CLAUDE.md`，要在其中寫 `@AGENTS.md`。
- 要跨工具（Codex、Copilot 等）通用，就用「索引表 ＋ 一般資料夾」。`paths:` 規則只當選配補強。
- 不確定某工具是否自動載入某檔案時，不寫死該行為，改在 `AGENTS.md` 明確指示。

## 寫法

- 用目標讀者的語言與專案的用語規範；只寫「為什麼」不顯而易見的部分。
- 主張要可驗證：路徑、指令、欄位名寫實際值，指令實際跑過。
- 禁令寫成可判斷的具體句子，不寫「盡量」「注意」。
- 不寫進度、待辦、歷史，交給 git log 或 changelog。

## 流程

先為每個情境做第 1 步：**列正本指派表**。

- **新建**：2 → 只寫核心（概述、禁令、驗證指令）；3 → 內容變多再依情境拆 guide；4 → 補索引表。
- **精簡**：2 → 逐段問「每個 session 都需要嗎」；3 → 不需要的搬進 guide 或刪掉（能從程式讀到的直接刪）；4 → 補索引表並修連結。
- **拆分**：2 → 依動手情境分組並命名；3 → 先搬後改；4 → 寫索引表與檔頭；5 → 修外部引用、`grep` 殘留與重複。
- **新增一份 guide**：2 → 確認沒有既有 guide 擁有這個主題，有就擴充它；3 → 補檔頭與索引表一列；4 → 對新內容的專有名詞 `grep` 查重。

## 完成前檢查

- [ ] 已列正本指派表，每個主題只有一處完整敘述（`grep` 驗證）
- [ ] 核心檔只剩每個 session 都需要的內容，索引涵蓋所有 guide
- [ ] 沒有字母章節編號或失效連結，相對連結指向的檔案都存在
- [ ] 文件裡的指令、路徑、數字已對照程式驗證；沒跑的檢查如實說明，不當成通過
- [ ] README、程式註解等外部引用已同步

## 與其他 skill 的關係

- 稽核現有文件的事實是否與程式一致，以及要不要加 `init.sh`、progress 等額外檔案：`agent-docs-audit`。
- commit 訊息與提交：`git-commit-msg`。互相依賴的引用改動，與被引用的檔案放同一個 commit。
